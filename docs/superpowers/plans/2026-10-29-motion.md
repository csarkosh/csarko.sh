# Material 3 Motion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every change on csarko.sh and the admin pages moves with Material 3 motion: accordions for folded admin sections, a glide for filtered lists, fades, slides and eased heights for the rest, and nothing at all under reduced motion.

**Architecture:** One set of motion tokens lives on `:root` in `public/index.html` beside the colour tokens, plus a reduced-motion block that zeroes the durations; `themeBlocks()` copies all three blocks into every generated page and into the admin's `theme.css`, and Day Hike's page reads them from the host's `/theme.css`. CSS transitions use the tokens directly; scripted effects (accordion, glide, cross-fade, eased height, menu, drawer) read them through one small helper module per codebase (`admin/public/motion.js` on the host, `client/src/admin/motion.ts` in Day Hike, the glide inside `filters.js` on the public site). Headless-Chrome checks in `check.py` prove the effects run and that reduced motion makes them instant.

**Tech Stack:** Plain CSS and ES modules (no framework), the Web Animations API, `@starting-style` for the popovers; Python `check.py` with headless Chrome; Day Hike in TypeScript with Vite and vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-motion-design.md`

## Global Constraints

- Tokens (exact): `--md-easing-standard: cubic-bezier(0.2, 0, 0, 1)`, `--md-easing-emphasized-decelerate: cubic-bezier(0.05, 0.7, 0.1, 1)`, `--md-easing-emphasized-accelerate: cubic-bezier(0.3, 0, 0.8, 0.15)`, `--md-duration-short2: 100ms`, `--md-duration-short3: 150ms`, `--md-duration-short4: 200ms`, `--md-duration-medium2: 300ms`, `--md-duration-medium4: 400ms`.
- Under `@media (prefers-reduced-motion: reduce)` every `--md-duration-*` is `0ms`, and no code waits on an animation to finish before the page is usable.
- No bare `ease`/`ease-in-out` or hand-picked duration remains in either site's CSS or scripts after this work (AGENTS.md, "Motion follows Google's Material 3 motion guidance").
- No new colours; no third-party code; CSP unchanged (no inline script); public pages stay under `BUDGET_SCRIPTS` (10,000 B; the list pages carry about 4.8 KB today).
- Lighthouse 100 accessibility and best practices, performance ≥ 95; `check.py` and `check.py --admin` pass; screenshots in both themes looked at.
- The no-jump work stays: held and remembered heights, skeletons from the first frame. The remembered height is always a card's final height, never a mid-animation one.
- The fade through (sign-in gate) uses `short2` out and `short4` in: the nearest M3 tokens to the spec's 90/210 ms.
- `/projects`' chips are single select (radios, All a reset); `/research`'s stay multi-select (checkboxes). The glide handles both: one `change` per click either way.
- csarko.sh work in the worktree `.worktrees/motion` on branch `motion`, merged to `master` at the end; Day Hike work in `.claude/worktrees/admin-motion` on `worktree-admin-motion` from fresh `origin/main`, gated by `test.yml`, commit messages in its `github-push` format. Day Hike deploys after the host (`npm run deploy:admin` publishes both).

## Review Focus

1. **Clicks during an animation** (a chip toggled twice inside 400 ms, an accordion clicked mid-open, a range changed twice quickly): the end state matches the last click, with no leftover ghost cards, inline heights or `overflow` styles.
2. **Reduced motion**: every effect is instant and every final state is the same as with motion (a fold open, a list filtered, a drawer shown).
3. **A filter link opened cold** (`/projects?filter=film`): the page paints already filtered, with no glide from the unfiltered list.
4. **Width changes**: after a resize, the next glide starts from where cards are now, not from positions cached at the old width.
5. **Find-in-page and keyboard on folds**: Enter/Space on a summary animates like a click; a fold opened by the browser itself (find-in-page) or by script just opens, without breaking the next click.

### Task 3: Admin motion module

**Files:**
- Create: `admin/public/motion.js`
- Create: `admin/test/motion.test.mjs`
- Modify: `admin/README.md` (the module, one row), `admin/CONTRACT.md` only if Day Hike would import it (it does not: it mirrors it)

**Interfaces:**
- Produces (all exported from `/motion.js`; no DOM access at import time):
  - `parseDuration(value: string, fallback = 0): number`: `"150ms"` → 150, `"0.3s"` → 300, `"0ms"` → 0, `""` → fallback.
  - `tokens(): { standard, decelerate, accelerate: string; short2, short3, short4, medium2, medium4: number }`, read once per call from `:root`.
  - `accordion(details: HTMLDetailsElement): void`: wires the summary as in the spec (open: body height 0 → full over `medium2` standard, rows fade in `short3` from 75 ms; close: rows fade `short2`, height → 0 over `short4` accelerate, then `open = false`); ignores clicks while running; a `toggle` it did not cause just opens or closes.
  - `easeHeight(el: HTMLElement, from: number, to: number): Animation | null`: `medium2` standard; `null` when `from === to` or the duration is 0.
  - `fadeIn(el: Element, duration?: number): Animation | null` and `fadeOut(el: Element, duration?: number): Animation | null`: standard / accelerate.
  - `glideList(host: HTMLElement, change: () => void, keyOf: (el: Element) => string): Promise<void>`: FLIP across a re-render that replaces the children; old and new children are matched by `keyOf`; unmatched new children arrive, unmatched old ones leave as ghosts; the host's height eases. Same timings as the public glide.
  - `showMenu(menu: HTMLElement): void` / `hideMenu(menu: HTMLElement): void`: scale 0.92 → 1 and fade from the top-right corner, `medium2` decelerate; out `short3` accelerate, `hidden` set when done.
